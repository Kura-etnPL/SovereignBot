# V4.2 P4 — LAN / Remote Worker secure pairing and transport

Date: 2026-09-02

## Delivered boundary

- `src/worker-secure-transport.js` adds one protocol for `lan` and `remote-relay` using durable device identities, signed one-time pairing offers/responses, X25519-derived session keys, AES-256-GCM payload encryption, signatures, sequence replay protection, exact protocol/version checks, and key epochs.
- `src/worker-trust-store.js` durably stores the local private device identity and trusted peer records. Pairing challenges are one-use and short-lived; records support expiry, explicit revoke, and rotation/re-pair.
- The encrypted payload is only `computer.health` or a validated `sovereign-worker-computer/1` envelope. No shell, cwd, env, arbitrary command, raw path, provider credential, continuation/session/browser profile, cookie, or token is admitted.
- `createOpaqueRelay()` forwards only the encrypted frame. Its observable metadata contains protocol, transport, device IDs, session/counter/epoch, and ciphertext fields; it cannot inspect bounded payload plaintext.
- Desktop Advanced Worker registry projects only safe trust state (`pending`, `trusted`, `revoked`, `expired`, `rotating`), transport, epoch, and timestamps. Existing loopback Bearer pairing remains unchanged.
- `ComputerTargetController` remains the authority for target, workspace, health, capacity, lease, cancellation, audit, and Attention behavior. There is no silent local fallback.

## Offline real canary

`tests/worker-secure-transport.test.js` passed:

- isolated Win32 and Linux identities pair mutually with a short-lived one-time code;
- trusted workspace health/action succeeds through an opaque remote relay;
- reconnect/new session remains usable and duplicate request identity remains bounded;
- ciphertext tamper, frame replay, wrong identity, protocol downgrade, expiry, and revoke fail closed;
- identity key epoch rotation requires re-pairing before the new session is accepted.

`desktop/test/p4-worker-secure-transport-canary.test.mjs` passed:

- the Desktop registry pairs and projects a LAN trust record without exposing endpoint/private state;
- the existing Job, Routine, Event Trigger, and Team dispatcher paths execute the selected secure Worker Computer;
- bounded takeover/release, capacity exhaustion, revoke, audit, Attention, and no-fallback behavior are covered;
- relay inspection contains no bounded payload text.

This acceptance is intentionally offline: LAN socket discovery and third-party relay deployment are outside this milestone. The same authenticated opaque frame contract is the transport boundary for either an authenticated LAN forwarder or an end-to-end encrypted broker/relay.
