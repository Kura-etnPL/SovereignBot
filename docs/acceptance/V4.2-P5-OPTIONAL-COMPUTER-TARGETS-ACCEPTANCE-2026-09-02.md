# V4.2 P5 Optional Computer Targets Acceptance — 2026-09-02

Scope: Canonical Product Plan P5 Optional execution targets: This PC, LocalIsolated, trusted Worker/VM, and opt-in CloudComputer.

## Boundary

- Job, Routine, Event Trigger, and Team Computer work continues through one Desktop Computer target controller and the bounded Worker Computer protocol.
- LocalIsolated attaches only to an existing Docker runtime. The adapter uses an ephemeral `ubuntu:24.04` container with no network, a read-only root filesystem, dropped Linux capabilities, no-new-privileges, bounded CPU/memory/PIDs, and one trusted workspace bind mount. There is no shell, cwd, raw path, environment, credential, or session field in the public contract.
- LocalIsolated supports real snapshot plus workspace-relative list/read/write actions, bounded timeout/cancel, `--rm` cleanup, lease state, audit, and Attention on help/failure. GUI actions fail closed as unsupported.
- VM targets are profiles over a trusted secure Worker Computer. VM resolution requires secure LAN/remote-relay trust, the advertised workspace/computer identity, health, capacity, capability, lease, replay, and audit checks. No hypervisor or VM is provisioned by this change.
- Cloud targets are provider-neutral profiles over the same trusted Worker Computer protocol. No cloud profile is configured by default; external cloud execution is therefore unavailable. Any configured profile requires main-process opt-in, trusted estimate/budget/per-run/total caps, health/runtime checks, and idempotent settlement.
- Public target projections expose only kind, opaque profile/worker identifiers, state, isolation, capabilities, cost estimate, currency, and budget fields. Endpoint, raw path, provider credential, transport secret, and session continuity remain private.
