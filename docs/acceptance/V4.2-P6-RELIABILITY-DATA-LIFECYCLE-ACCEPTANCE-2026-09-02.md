# V4.2 P6 Reliability + Data Lifecycle Acceptance — 2026-09-02

Scope: Canonical Product Plan §34, first phase: restart recovery boundaries, provider health continuity, versioned Desktop state migration, local backup/restore, redacted export, and confirmed product-state reset.

## Implemented boundary

- A single Desktop data-lifecycle service runs before Desktop services are constructed and wraps the existing core state-transfer authority. It records a V3-to-V4 lifecycle marker idempotently and creates a pre-migration backup before committing the marker.
- Desktop backup bundles use an explicit allowlist for core state, safe Desktop product registries, and managed artifact files. Every entry is regular-file checked, bounded, hashed, and validated before restore. Bundle paths, parent components, credential/authority filenames, traversal, and symlink entries fail closed.
- Restore is staged and hash-verified, creates a pre-restore backup, and replaces only product state. Computer registry, browser/driver state, Worker credentials/trust, controller state, relay material, policy state, and audit history are not portable Desktop-backup payloads and are retained on the destination.
- Export is redacted and non-restorable. It includes core aggregate export metadata, sanitized Desktop registry metadata, and managed artifact content addressed only by opaque artifact id plus relative export path and SHA-256. Renderer IPC never receives a filesystem path.
- Clean reset requires a newly prepared backup, an opaque confirmation nonce, and the matching backup id. It stops schedule/watch activity, requests release of task-bound Computer leases, cancels active Computer controller work, and removes only product state. Protected Computer/credential/browser/Worker/controller state remains.
- Existing Job/Routine/Event Trigger restart reconciliation and provider roster health states remain the runtime authority: `ready`, `signed-out`, `capacity-limited`, and `unavailable` are surfaced without provider fallback or continuity leakage. No second runtime or alternate executor was introduced.

## Unavailable or intentionally deferred boundaries

- No external cloud backup, cloud restore, provider credential export, browser-profile export, relay-secret export, or portable private-key export is supported.
