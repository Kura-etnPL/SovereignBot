## Delivered behavior

- Push-to-talk uses Chromium Web Speech recognition when available. It accepts pointer and keyboard hold/release, uses `system`, `zh-CN`, or `en`, and appends the final transcript only to the currently open composer; it never sends automatically.
- Optional reply speech is off by default. Only the main-process trusted `voiceEligible` marker can authorize a terminal Coworker reply; user messages, internal protocol text, handoffs, reviews, Attention, mentions, pending delivery, and sensitive metadata are excluded.
- Spoken text is normalized and capped at 1,200 characters. Conversation/message keys are bounded and deduplicated; switching conversations or restarting does not replay history.
- Stop and mute cancel current recognition/playback. Conversation/view changes, the conversation Stop action, Computer/This PC Take Over, and app unload/pagehide also stop voice.
- Settings expose language, Speak replies, Mute voice, an accessible Stop control, and a live status region. Unsupported recognition and denied microphone permission are reported without claiming availability.
- The implementation is Web Speech/OS-only. There is no `MediaRecorder`, `getUserMedia`, raw-audio field, audio persistence, voice-call transport, telephony, or provider credential path.
