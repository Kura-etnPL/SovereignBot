## Delivered behavior

- Ordinary users have an independent `Apps Catalog / 应用目录` page with browse, bounded search, category filtering, connection/lifecycle status filtering, and Project scope selection.
- Each public app row shows trusted source, version, capability summary and detail, approval summary, catalog availability, installation state, connection state, health, and cost/metering explanation. Catalog availability is not presented as a ready connection.
- First-party `This PC / 此电脑` and `Project workspace / 项目工作区` entries are real existing governed local lanes. Unconfigured entries remain unavailable/attention rather than pretending to be connected.
- Connecting requires an in-page capability/approval/cost review. Metered manifests require explicit `approveMetered` consent in the trusted main service; current first-party entries are included/no-additional-metered-fee.
- Users can connect, disconnect, or disable an app and assign it at Team, Coworker, or Project scope. Disconnect removes assignments; disable persists the assignment but revokes usable Coworker tools. Restart reloads both lifecycle and scoped assignment state.
- Manifest input is fail-closed: exact schema/version, 64 KiB manifest size, allowlisted fields, bounded identifiers/strings/lists, category, lifecycle, cost, and approval metadata are validated. Unknown authority, shell, cwd, environment, provider-session, credential, raw-path, URL, transport, and policy fields are not accepted.
- Renderer projections and review data contain no OAuth token, MCP URL, adapter internals, transport, raw schema, local path, credential, or session/profile material. Only the trusted main process binds adapters/tools and invokes the Governor bridge.
