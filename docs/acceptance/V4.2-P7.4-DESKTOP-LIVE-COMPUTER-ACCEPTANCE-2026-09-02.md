## Delivered behavior

- This PC is a status-first local Desktop page with one safe card per Coworker in the selected Project. Each card shows status, health, current work, current app/site when available, shared/private context, safe activity, recent files, and Project artifacts.
- The page has an honest empty latest-screen state. A user-triggered latest-screen action accepts only bounded PNG/JPEG/WebP base64 frames and exposes only an allowlisted site host; invalid or unavailable frames fail closed.
- Page details are projected through the existing safe Computer snapshot path. Snapshot IDs, element refs, roles, names, and types are bounded; backend handles, browser sessions, paths, and credentials are not returned.
- Take Over and Hand Back remain existing Computer control operations. Take Over immediately blocks TaskBound agent Computer side effects through the existing Governor path. Hand Back releases the human control, proves re-entry through the running TaskBound snapshot path, and restores human control if reacquisition fails.
- Shared-login Coworkers in one Project use a single service-side read-operation queue, so concurrent This PC screen/detail reads are serialized for the shared context. Private contexts retain separate Coworker affinity and cannot reuse a profile identity.
- Files, artifacts, and Computer history are safe summaries with direct navigation to the existing Files & Artifacts and Computer History product pages. Navigation uses existing product surfaces and does not create a parallel history store.
- Health, unsupported-frame, unavailable/permission/attention, empty, and clean-restart/corrupt-state outcomes are explicit. Internal Computer, driver, lease, profile, path, token, session, provider-account, and authority values remain outside the ordinary This PC UI projection.
