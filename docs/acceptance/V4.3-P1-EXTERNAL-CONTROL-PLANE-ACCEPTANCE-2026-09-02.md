## Scope

This increment adds a paired-device External Control Plane while preserving the existing operator-session loopback MCP server for compatibility. The secure facade has exactly these operations:

`listTeams`, `listCoworkers`, `listChannels`, `sendMessage`, `getConversation`, `submitOutcome`, `getStatus`, `cancel`, `getArtifacts`, `listSkills`, `listRoutines`, `runRoutineNow`, `getAttention`, `requestTakeover`.

`getStatus` and `cancel` are the secure facade names for the existing bounded outcome status/cancel authority. No generic IPC, shell, filesystem, provider-session, credential, continuation, or policy mutation operation is registered.

## Authority and projection result

- Secure requests use the existing mutual Worker device identity, key epoch, trust TTL, sequence/replay checks, AEAD frame authentication, and either direct or opaque relay transport.
- Desktop stores only controller grant metadata in `desktop-state/external-controllers.json`; public projections contain opaque device/team/project IDs, scopes, health, status, and last-seen timestamps, never private keys, paths, provider sessions, cookies, tokens, or credentials.
- Every secure call is re-authorized against the paired trust record, explicit scope, and Team/Project binding. External input cannot mint a capability or select an authority-bearing execution context.
- The registry enforces the current paired transport and a maximum of eight in-flight requests per controller; transport mismatch and capacity exhaustion fail closed.
- Messages/outcomes use the existing `conversationStore`, `dispatchMessage`, outcome ledger, artifact reference validation, routine controller, jobs/Attention, Computer takeover callback, cancellation block, and audit log.
- Duplicate `clientRequestId` values are idempotent only when the normalized body hash matches; a different body is rejected as a conflict.
- Advanced UI shows only paired controller safe metadata, scopes, health/last seen, revoke, and rotate actions.
