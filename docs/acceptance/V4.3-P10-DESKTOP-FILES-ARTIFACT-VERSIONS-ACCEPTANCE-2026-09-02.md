## Delivered slice

The local Files & Artifacts path now supports:

`Files & Artifacts → inspect / preview / open / reveal → History → select a version → Restore as new version`

- Existing ArtifactStore records are backward-compatible: old entries receive family `artifactFamilyId` and `version: 1` on load.
- A revised version is created through a main-process-owned secure local-file picker; the renderer sends only the opaque artifact ID and cannot provide a path.
- Restore copies bytes from any selected main-process managed artifact into a new immutable record in the same `artifacts.json` and managed storage, with `artifactFamilyId`, `version`, and `parentArtifactId`.
- The Hub renders a selectable per-version History with a Restore action for each retained version; v1 can be restored after v2 has different bytes.
- The Hub shows the latest public version per family while preserving the existing Conversation, workspace/Project association, Team, Channel, and Coworker projections.
- History, revise, and restore requests are enumerated, bounded, identifier-only IPC channels; renderer code never receives a filesystem path.
- Restored content is public only because the source artifact was already public; no upload, sharing, cloud sync, retention, deletion, scheduler, provider, OAuth, or capability path was added.
- Restores invalidate the existing Search index through the established mutation channel set.
