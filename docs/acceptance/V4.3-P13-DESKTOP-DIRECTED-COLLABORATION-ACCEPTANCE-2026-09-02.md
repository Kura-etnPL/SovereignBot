## Delivered slice

Team Channel details now provide a bounded collaboration control for the current owner:

- send a bounded task to any active teammate in the same Team;
- request a review from any active teammate, including a non-hardcoded Specialist;
- return ownership through the same explicit handoff action after a review result.

The main process derives the current owner from durable Team flow state and validates the managed Channel, target membership, active availability, runtime preflight, single-owner invariant, and duplicate/runaway guards. Renderer input is limited to `conversationId`, `targetCoworkerId`, `handoffType`, `reason`, and `boundedTask`; forged owner, provider, capability, token, path, or session authority is rejected by the existing validated IPC boundary.

Successful requests reuse the existing TeamService protocol, collaboration ledger, Conversation store, dispatcher wake path, and public activity projection. The owner changes once to the selected target, the bot-to-bot message mentions only that target, and no new executor, workflow engine, App/Skill grant, Governor authority, or provider run is introduced. Safe bounded task/reason fields persist in the active protocol and survive restart.
