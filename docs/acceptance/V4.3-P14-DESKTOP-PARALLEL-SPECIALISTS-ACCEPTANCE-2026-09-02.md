## Delivered slice

The normal-user Team Channel now exposes a bounded parallel action. The renderer submits exactly `conversationId`, `children`, `reviewerCoworkerId`, and `reason`. Each child contains only `targetCoworkerId`, `boundedTask`, and optional `requiresComputer`. The main process derives the current owner from the durable Team flow and reuses the existing `TeamService.requestFanout` and `coworker-dispatcher` path.

The flow is controlled as:

`current owner → 2–4 isolated Specialists → independent reviewer → original owner join → final public result`

The UI provides two initial Specialist rows, supports up to four, excludes the current owner, requires a separate reviewer, shows bounded progress, and disables the existing collaboration action while a fanout is active. Active and final projections contain human-readable names, bounded task/result text, status, counts, and Artifact metadata only.
