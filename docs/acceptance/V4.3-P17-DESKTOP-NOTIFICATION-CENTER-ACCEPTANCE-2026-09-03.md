## Delivered slice and Sol acceptance hardening

The desktop shell now features a hardened, first-class local Notification Center that allows users to find and review important events after transient Windows desktop notifications disappear.

The implementation strictly reuses `desktop/src/main/notification-service.js` and `desktop-state/notifications.json` as the single durable store, preserving the exact five allowlisted categories: `attention`, `routine-completed`, `trigger-fired`, `coworker-finished`, and `channel-unread`. No second event store, scheduler, executor, authority model, notification transport, or generic navigation mechanism was introduced.

### Gaps addressed per Sol acceptance review:

1. **Safe Host Event Navigation**:
   - Wired conversation notifications to dispatch `sovereignbot:navigate-conversation` on the document, handled safely by `app.js` calling `openConversation(conversationId)`. Renderer never receives arbitrary URLs, commands, or authority.
   - Routines notifications activate the dynamic Routines surface via `#nav-routines` click with `sovereignbot:navigate-routines` event fallback.
   - Real hidden Electron gate coverage verifies that clicking navigation buttons directly activates the corresponding surfaces.

2. **Public Key Removal and Collision-Resistant Opaque IDs**:
   - Removed internal dedupe keys from all public notification projections, UI state, API results, and evidence.
   - Migrated legacy records deterministically to collision-resistant opaque IDs (`notif_[a-f0-9]{16}`) without leaking internal key semantics.
   - Renderer mutations, find operations, and batch matching (`markRead`, `clear`, `markAllRead`, `clearAll`) accept only valid opaque IDs; raw internal keys are strictly rejected.
   - Tightened IPC validator (`validateNotificationRequest`) to enforce the opaque notification identifier pattern.

3. **Exact Safe Source Projections**:
   - Projected sources are exact per target: `conversation` requires `conversationId`, `routines` requires `routineId`, `triggers` requires `triggerId`, `work` requires `jobId`, `artifacts` requires `artifactId`; `attention` may carry optional `jobId`.
   - Incomplete or malformed targets are dropped to null, preventing dead or no-op navigation buttons. Irrelevant or authority fields are stripped.

4. **Trusted Boundary Redaction**:
   - Deterministic bounded redaction implemented at the notification service boundary (`cleanAndRedact`) covering `title` and `body`.
   - Secrets, tokens, cookies, `Authorization`/`Bearer` headers, and Windows/UNC/Unix absolute paths are redacted before persistence, public projection, or popup delivery.
   - Normal UI copy does not expose local filesystem storage paths.

5. **Monotonic Refresh Generation Guard**:
   - Added an incrementing `refreshGeneration` counter to `notifications-ui.js`. In-flight async responses that complete after a newer filter or action refresh are safely discarded.
   - All dynamic text remains strictly bound to DOM text nodes (`textContent`).

6. **Honest Channel-Unread Boundary**:
   - Documented that while `channel-unread` is an allowlisted category supported in storage, UI, and filters, no automated production main-process event hook currently exists. Notifications in this category are recorded only when explicitly requested.

## Honest limitations

The hidden fixture exercises trusted local notification state transitions, real sandboxed preload, validated IPC, DOM rendering, real conversation/routines/attention surface navigation, and restart persistence under the real Electron runtime; it does not trigger external Windows OS toast clicks directly, nor does it create a background network sync or mobile push relay. Automated production hooks for `channel-unread` remain unwired in the main process pending a trusted background unread event source. The notification store remains local, privacy-first, and bounded at 500 events.
