## Delivered slice and Sol acceptance hardening

The desktop shell features a hardened, first-class local Notification Center that allows users to find and review important events after transient Windows desktop notifications disappear.

The implementation strictly reuses `desktop/src/main/notification-service.js` and `desktop-state/notifications.json` as the single durable store, preserving the exact five allowlisted categories: `attention`, `routine-completed`, `trigger-fired`, `coworker-finished`, and `channel-unread`. No second event store, scheduler, executor, authority model, notification transport, or generic navigation mechanism was introduced.

### Gaps addressed per Sol acceptance review and second-pass hardening:

1. **Single Safe Conversation Navigation Route**:
   - Dispatches exactly one safe host event `sovereignbot:navigate-conversation` on the document, handled safely by `app.js` calling `openConversation(conversationId)`. Eliminated duplicate navigation button clicks in sidebar.
   - Routines notifications activate the dynamic Routines surface via `#nav-routines` click with `sovereignbot:navigate-routines` event fallback.
   - Hidden Electron gate verifies that conversation navigation loads the intended conversation identity, channel title, and message content without handler errors on `team:activity`.

2. **Complete Trusted-Boundary Redaction and Digest Key Identities**:
   - Generic credentials in `Authorization: Bearer <arbitrary-val>`, `Authorization Bearer <arbitrary-val>`, `Basic <arbitrary-val>`, and `Cookie: <arbitrary-val>` headers are completely redacted without leaving credential tails behind.
   - Notifications store dedupe identities on disk as stable sha256 digests (`k_[a-f0-9]{32}`) rather than raw key strings, preventing secret, token, and path leakage into `notifications.json`.
   - Preserves deterministic deduplication across service restarts and backward-compatible migration for legacy un-hashed records.
   - Regression canaries verify that raw credentials not matched by `sk-`/`ghp_` prefixes do not enter disk, public projections, or popups.

3. **Stale Refresh Generation Guard Covering Success and Failure**:
   - Monotonic `refreshGeneration` counter guards both the success path and the `catch` failure block in `notifications-ui.js`.
   - Stale async responses or stale network rejections returning after a newer filter or action refresh are discarded before any UI mutation.
   - Real renderer gate test verifies that neither stale success nor stale failure overwrites the active view.

4. **Public Key Removal, Opaque IDs, and Exact Source Projections**:
   - Public projections completely omit internal dedupe keys and expose only collision-resistant opaque IDs (`notif_[a-f0-9]{16}`).
   - Mutations strictly accept only opaque IDs; raw internal keys are rejected at the IPC validator and service find methods.
   - Source projections enforce exact per-target schemas, dropping incomplete/missing IDs to null and stripping dangerous authority fields.

5. **Honest Channel-Unread Boundary**:
   - Documented that while `channel-unread` is an allowlisted category supported in storage, UI, and filters, no automated production main-process event hook currently exists. Notifications in this category are recorded only when explicitly requested.

## Honest limitations

The hidden fixture exercises trusted local notification state transitions, real sandboxed preload, validated IPC, DOM rendering, real conversation/routines/attention surface navigation, stale refresh guards, and restart persistence under the real Electron runtime; it does not trigger external Windows OS toast clicks directly, nor does it create a background network sync or mobile push relay. Automated production hooks for `channel-unread` remain unwired in the main process pending a trusted background unread event source. The notification store remains local, privacy-first, and bounded at 500 events.
