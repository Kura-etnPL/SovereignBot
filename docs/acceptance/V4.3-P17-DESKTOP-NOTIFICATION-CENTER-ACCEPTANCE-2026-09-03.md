## Delivered slice

The desktop shell now features a first-class local Notification Center that allows users to find and review important events after transient Windows desktop notifications disappear.

The implementation strictly reuses `desktop/src/main/notification-service.js` and `desktop-state/notifications.json` as the single durable store, preserving the exact five allowlisted categories: `attention`, `routine-completed`, `trigger-fired`, `coworker-finished`, and `channel-unread`. No second event store, scheduler, executor, authority model, notification transport, or generic navigation mechanism was introduced.

Key delivered capabilities:
- **Obvious entry and unread badge**: The sidebar navigation displays a prominent Notifications button (`#nav-notifications`) with a live unread count badge (`#notifications-badge`).
- **Bounded newest-first inbox**: Cards render with human bilingual category labels, relative time, timestamps, titles, bodies, and read/unread status badges.
- **Durable mutations with restart safety**: Supports marking single items read/unread, marking all visible read, and dismissing/clearing single items or all visible notifications. All mutations persist durably to `desktop-state/notifications.json` and survive application restarts.
- **OS preference preservation**: When OS popup notifications or specific category popups are disabled in user settings, safe inbox events continue to be recorded and persisted durably so users can discover them in Notification Center without annoying desktop popups.
- **Safe source navigation**: Notifications carry explicit allowlisted navigation metadata (`attention`, `routines`, `triggers`, `work`, `conversation`, `artifacts`) using only opaque product identifiers. Dangerous fields (`command`, `cwd`, `token`, `session`, `path`, `url`) are strictly rejected and stripped before persistence and projection. Cards without a safe target render cleanly without navigation links.
- **Renderer safety and XSS prevention**: Dynamic text is rendered strictly via DOM text nodes (`textContent`), never `innerHTML`.
- **Enumerated IPC channels**: `notification:list`, `notification:markRead`, `notification:markAllRead`, `notification:clear`, and `notification:clearAll` are registered with exact-key schema validation and payload size caps. The renderer has no capability to forge or inject arbitrary notifications.

## Honest limitations

The hidden fixture exercises trusted local notification state transitions, real sandboxed preload, validated IPC, DOM rendering, and restart persistence under the real Electron runtime; it does not trigger external Windows OS toast clicks directly, nor does it create a background network sync or mobile push relay. The notification store remains local, privacy-first, and bounded at 500 events.
