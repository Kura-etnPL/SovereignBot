## Delivered Slice & Architectural Closure of P17 Limitation

SovereignBot Desktop P18 delivers a trusted production channel-unread notification producer that closes the explicit P17 limitation recorded in `handoff/HANDOFF.md`.

The implementation directly integrates the existing `ConversationStore`, `TeamService`, and `NotificationService` without introducing a second event system, database, scheduler, or generic renderer-create IPC.

### Architecture and Reviewer-Directed Hardening:

1. **Fail-Closed Intent Architecture (Zero Text/Regex Heuristics)**:
   - Eliminated text-matching and regex-based heuristics (`isInternalOrHarnessNoise` was rejected and removed).
   - Default fail-closed: coworker messages produce a channel-unread notification strictly when explicit call-site metadata sets `notifyChannelUnread === true`. If `undefined` or `false`, no notification is produced.
   - Audited production callsites across `coworker-dispatcher.js` and `team-service.js`: fanout child/review/join stages, collaboration requests, intermediate playbook steps, and handoff turns are explicitly marked with `internal: true, notifyChannelUnread: false`.
   - Only published, terminal, user-facing results (both standard unmanaged teams and managed playbook sequences via `previewHandoffDecision`) opt in to `notifyChannelUnread: true`.

2. **Read-Only `conversation:get` and Explicit Acknowledgment Path**:
   - `conversation:get` is strictly read-only and never resolves unread state.
   - Added bounded `conversation:acknowledge` IPC handler calling `notifications.resolveChannelUnread(conversationId)`.
   - Schema validation in `v3-ipc-schema.js` enforces exact payload: `{ conversationId }` matching valid ID pattern, rejecting arbitrary properties or authority.

3. **Promise-Chained UI Acknowledgment & Badge Synchronization**:
   - In `desktop/ui/app.js`, `markConversationRead` saves local read markers synchronously to prevent UI latency.
   - Invokes `window.sovereignbot.conversations.acknowledge`, promise-chains the IPC call, catches async errors safely without crashing the UI, and dispatches `sovereignbot:refresh-notifications-badge` strictly after backend persistence settles.
   - All channel-opening flows (sidebar channel click, channels view click, Notification Center card navigation button, and direct navigation events) converge on this path.

4. **Predictable Per-Channel Coalescing & Reactivation**:
   - Subsequent unread messages in the same channel update the existing notification card in-place (updating body, title, timestamp, and safe source) without creating duplicate cards or spamming OS popups.
   - When a channel notification was previously read or dismissed, new eligible coworker activity reactivates the card to unread, updates the content, and triggers an OS popup if enabled.

5. **Security, Privacy & Redaction Preserved**:
   - Internal keys are never exposed to renderer projections or IPC arguments.
   - Stable dedupe keys are hashed to sha256 digests (`k_[a-f0-9]{32}`) on disk.
   - Secret tokens (`sk-`, `ghp_`, Bearer, Basic, Cookie) and Windows/Unix absolute paths are redacted at the service boundary before persistence, public projection, or popup delivery.
