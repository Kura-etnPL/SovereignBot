## Delivered

- Skills have a structured dialog editor for name, description, instructions, source/type, expected output, inputs, steps, validators, and requested capability declarations.
- Inputs, steps, and validators support bounded add, remove, and reorder actions. Save and Cancel are separate; dialog validation errors remain in the dialog. Archived Skills open read-only and must be restored before editing.
- Duplicate, Archive/Restore, Retest definition, Team/Coworker assign/unassign, and Create Routine remain connected to the existing typed services and event boundary.
- Native JSON import/export runs through main-process Electron dialogs and bounded file IO. The renderer receives only cancellation, basename, byte count, or sanitized result data. The portable definition excludes lifecycle and authority state; imports reject capability grants, tokens, sessions, credentials, raw paths, URLs, and unknown authority fields. `requestedCapabilities` is declarative only and never grants access.
- Skill persistence keeps lifecycle metadata separate from the portable definition. The governed retest path was corrected to persist `lastTestedAt` and `updatedAt`; the loader already preserved the separation and needed no further change.
