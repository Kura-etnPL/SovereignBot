## Scope

P25 closes the remaining local Memory product UX gap identified after the broader V4/P2–P6 audit. The Memory service and authority model were already complete; the independent Memory page still edited a durable record through two renderer `window.prompt` calls and could not edit tags.

- Added a bounded in-product Memory Edit dialog for title, content, and comma-separated tags.
- Cancel closes without a write. Empty required values, tag-count overflow, and trusted IPC errors remain in-dialog and sanitized.
- The edit request uses the existing `memory:update` typed preload/IPC path with the captured scope and owner; no scope, provenance, authority, credential, session, or path fields can be supplied by the form.
- Existing Coworker private, Team shared, and Project-scoped Memory behavior, suggestion approval, pin/forget/delete, source trace, bounded retrieval, Project Search indexing, and restart persistence remain on the canonical stores/services.
- Search was audited but not rewritten: it already covers Conversations, Channels, Coworkers, Projects, Artifacts, Skills, Playbooks, Routines, Memory, Jobs, and History with Project scoping, relevance ordering, bounded limits, `hasMore`, deep links, and authority-free public projections.
