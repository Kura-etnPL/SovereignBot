# V4.3 P36 First-run / Onboarding acceptance

Date: 2026-09-03
Scope: Canonical Product Plan §38 First-run / Onboarding

P36 adds a clear `Create a coworker / 新建同事` action to Welcome. The action uses the existing `resetCoworkerDialog`, `populateCoworkerAdvanced`, and `saveCoworker` path; it does not create a second coworker flow. `Install Software Team / 安装软件团队` remains the first and primary Welcome action.

Welcome copy is connected to the existing English/Simplified Chinese i18n table. Provider readiness is a renderer projection of the trusted public roster only: when Codex is unavailable it shows `Connect Codex / 请连接 Codex`; when the Deep lane (ChatGPT Web / Sol) is unavailable it shows `Deep unavailable · Connect ChatGPT Web / Deep 暂不可用 · 请连接 ChatGPT Web`. No catalog, credential flow, login, or network behavior was added.

## Evidence

The hidden Electron fresh-state canary passed 10/10 using a task-owned temporary Electron profile, task-owned temporary application data, the real `sovereignbot://app/` window, sandboxed preload, validated IPC, and canonical Coworker/Conversation stores:

- Welcome is visible on fresh start.
- Create Coworker opens the real creation dialog with advanced workspace controls.
- The created Coworker persists through the canonical IPC path and automatically opens a real Direct conversation.
- A UI reload preserves the Coworker and Direct conversation and reopens it from the rendered Coworker list.
- The Software Team install button remains present as the primary action.
- Disconnected Codex and Deep states are projected honestly and separately.

Evidence: [`verify-p36-first-run.json`](verify-p36-first-run.json) and [`verify-p36-first-run.log`](verify-p36-first-run.log). `fixtureBoundary=LOCAL_FIXTURE`; `publishEligible=false`; no provider account, login, network, browser, user data, deployment, or external action was used.
