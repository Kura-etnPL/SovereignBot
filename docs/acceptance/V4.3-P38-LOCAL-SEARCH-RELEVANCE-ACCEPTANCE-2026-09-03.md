# V4.3 P38 local search relevance acceptance

Date: 2026-09-03
Scope: Canonical Product Plan §40 local Search relevance

P38 upgrades the desktop global Search index with deterministic, explainable local ranking. Title exact/prefix/contains, phrase, structured Memory tags, subtitle, content/search text, and token matches receive bounded enum reasons and stable scores. Multi-word partial matches require useful coverage and a strong title/tag signal, preventing weak content noise. Existing type/status/project filters, pagination, `hasMore`, navigation, and result ordering remain compatible.

Memory tags are indexed as a separate structured field and are never returned as raw search data. Public results expose only the safe `matchReason` projection: an allowlisted key, matched field names, and bounded coverage. The Search palette appends a short English/Simplified Chinese reason to the existing result subtitle without changing keyboard, filtering, or navigation behavior.

The change also corrects the artifact-store `visibility: "all"` predicate so archived artifacts can be indexed and then filtered by the existing Search status contract.
