# V4.3 P39 Conversation pagination acceptance

Date: 2026-09-03
Scope: Canonical Product Plan §35 long Conversation history

P39 keeps `ConversationStore.get(id)` as the complete main-process read for dispatchers and internal callers, and adds the same-store bounded `getPage()` path for renderer reads. The typed `conversation:get` contract now accepts only `conversationId`, `limit` (1–100), and an existing conversation-local `beforeMessageId`; omitted limits normalize to 100. The response preserves the existing summary and message fields and adds `pageInfo.total`, `pageInfo.hasOlder`, and an opaque next cursor. Unknown, stale, and foreign cursors fail closed.

The ordinary Conversation UI initially renders the latest 100 messages, loads older pages through an explicit `Load older messages / 加载更早消息` action, prepends them in order without duplicates, and restores the scroll anchor after layout. The bounded 300-row window slides toward older history as more pages are loaded; once the visible window leaves the live edge, polling updates totals without replacing that historical window and exposes an explicit `Back to latest / 回到最新` action with a new-message count. The action reloads the latest page and returns the scroller to the live edge. Conversation switches reset pagination state, and rendered message DOM is capped at 300 rows. Existing send, reply, mention, delivery, voice, mark-read, Team activity, and navigation paths remain on the existing typed APIs.

## Evidence

The strengthened hidden Electron canary is implemented for a 450-message fixture and verifies the real `sovereignbot://app/` window, sandboxed preload, validated IPC, canonical local ConversationStore, task-owned Team/Conversation fixtures, three successive older-page loads into a 300-row historical window, polling stability/new-message prompt, explicit return to latest, switch isolation, fail-closed cursors, and restart persistence. In this Luna host run, the canary reached the hidden-window assertion but the renderer failed to launch (`exitCode=49`), so no canary business assertions are claimed as passed here. The independent minimal Electron renderer probe and the existing P38 canary also reproduce `ERR_FAILED (-2)`, identifying a host smoke-environment blocker rather than a P39 assertion result. The evidence JSON is intentionally marked `ok=false` for this run.

The canary is designed to verify:

- default public page and initial DOM bounded to 100 messages for a 450-message conversation;
- public projection excludes provider/session/credential/path-like internal fields;
- three real Load older clicks slide an ordered unique 300-row historical window and preserve the scroll anchor;
- a newly persisted message leaves the historical DOM unchanged while polling exposes a Back to latest/new-message action;
- explicit Back to latest reloads the newest bounded page and returns near the bottom;
- switching to another conversation clears the old page/window state;
- limit, unknown-field, and foreign-cursor requests are rejected at the typed IPC boundary;
- restart rebuilds the same latest page from the durable conversations JSON.
