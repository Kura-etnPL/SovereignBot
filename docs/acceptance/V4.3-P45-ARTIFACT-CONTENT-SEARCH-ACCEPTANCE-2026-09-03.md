## Delivered design

- Artifact content indexing uses the sole canonical `ArtifactStore`; no second database or renderer-side content index was introduced.
- Only allowlisted textual artifact MIME types are considered. Missing files, binary files, unreadable files, and files over the 64 KiB per-artifact bound are skipped. The search build is globally bounded to 5,000 artifact records.
- Search reads eligible managed text once during index construction, sanitizes sensitive path, URL, credential, and secret-like material before indexing, and returns only a bounded safe snippet (at most 180 characters) in the public result projection.
- Non-empty queries refine through the existing bounded candidate index before content scoring. Internal search text, managed paths, provider/session data, credentials, and other authority fields remain main-process-only.
- Artifact lifecycle changes invalidate the authoritative Search service through the ArtifactStore observer. Archive, restore, revise, discard, and restart behavior are covered by the real fixture lifecycle calls; archive filtering and restored/revised content are verified.
