## Delivered behavior

- Routine card Enable/Disable, Archive, and Remove actions now use the existing
  `routineActionPending` and per-card feedback path. A pending card disables its
  controls, preventing duplicate or cross-card mutations; failures leave the card
  state intact and expose a sanitized retryable error.
- Remove is persistent and therefore uses a non-blocking in-product confirmation
  dialog. The dialog names the selected Routine, explains that schedule/history are
  permanently removed, and points to Archive when recovery is desired. Cancel does
  not call the controller.
- Archive/Restore continues to use the existing controller lifecycle semantics; no
  second data layer or authority path was introduced.
- The focused regression and the existing P30 hidden Electron gate were extended in
  place. The P47 package command reuses that gate with the `routineActionsGate` path.
