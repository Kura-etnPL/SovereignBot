# V4.4 P1 — Android/Mobile + Remote Access Acceptance

Date: 2026-09-02
Scope: Canonical Product Plan §28 Android/Mobile and §29 Remote Access
Boundary: this slice delivers a WebView/PWA-hostable Remote Controller runtime, not an Android APK.

## Product boundary

- Android does not run Agent Runtime. Android and Web are lightweight Remote Controllers.
- The controller entry is `ui/controller.html` with `ui/controller-app.js`, `ui/controller.css`, a local manifest, and an offline cache worker.
- A trusted WebView/native host must inject the fixed controller bridge. The page has `connect-src 'none'` and never opens REST, WebSocket, direct IPC, provider, or shell paths.
- The host bridge reuses the paired §27 External Control Plane and §27 secure direct/opaque relay transport. Desktop must be online; the relay sees ciphertext and opaque routing metadata only.
- No Android SDK/native build environment was present or required in this worktree. No APK is claimed or emitted. Native packaging starts at the bridge boundary: the host owns device identity/private keys, pairing response, transport, lease cache, and secure channel implementation; the page owns only presentation and bounded calls.
- Mobile persistence is limited to the public controller projection and UI preference under `sovereignbot.remote-controller.public.v1`. It contains no private key, token, cookie, session, desktop credential, raw workspace/artifact path, worker secret, or relay plaintext. Logout calls the fixed host lease-clear/logout hooks and removes that cache key.
- There is no push notification implementation and no notification per handoff.

## Secure contract

The existing v1 14-operation surface remains wire-compatible. `external-control/2` adds only these four narrow operations:

| Operation | Input | Authority path |
| --- | --- | --- |
| `approveAttention` | `{jobId}` | existing Jobs Attention + controller `attention:decide` scope + Audit |
| `denyAttention` | `{jobId}` | existing Jobs Attention + controller `attention:decide` scope + Audit |
| `computerView` | `{projectId,coworkerId}` | existing Project/Coworker scope + `thisPc.list/health/snapshot`; read-only |
| `releaseTakeover` | `{projectId,coworkerId}` | existing `thisPc.handBack` + task-bound Computer lease + Governor path + Audit |

No generic Computer click/type/key/shell action is exposed. `requestTakeover` remains the existing v1 outcome/Attention operation. Computer view returns bounded status/activity and a governed snapshot; no raw paths, coordinates, credentials, sessions, or provider material cross the boundary.
