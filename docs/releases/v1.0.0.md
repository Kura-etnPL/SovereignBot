# SovereignBot 1.0.0

SovereignBot 1.0.0 is the first production release of the supported local-first core: durable multi-agent work, governed local computer/browser access, resumable Codex and Claude Code workers, a local operator surface, fail-closed policy/security boundaries, and explicit recovery/release engineering.

## Highlights

- **Local-first runtime.** Durable tasks, memory, progress, dependency graphs, supervisor delegation, retry/cancel flows, and independent review remain on the local runtime path.
- **Codex + Claude Code workers.** Provider sessions can be persisted/resumed while governed computer tools are exposed through a task-bound MCP bridge rather than broad ambient browser authority.
- **Governed computer use.** Per-agent profiles/workspaces, exact running-task ownership, hard navigation guards, operator takeover, and a dedicated secret-supply path keep worker authority constrained.
- **Operator console.** Short-lived operator sessions, passive worker state, telemetry, policy dry-run/apply/history/rollback, and computer control are separated from durable operator bearer authority.
- **Versioned policy.** Policy changes are dry-run checked, stored as immutable hashed versions, activated transactionally, audited, and recoverable after supported crash windows.
- **Diagnostics and recovery.** `sovereignbot doctor`, startup preflight, recovery quarantine, integrity-verified backup/restore, and redacted export make local state inspectable and recoverable without silently repairing unknown corruption.
- **Transactional migration.** The supported legacy v0.3 ComputerRegistry layout migrates to v2 with create-once recovery evidence, source/target/agent-set integrity binding, pre-commit rollback, and idempotent restart recovery.
- **Portable release path.** Deterministic tar.gz payloads, SHA-256 manifests, Windows PowerShell/POSIX installers, and CI coverage for install/reinstall/rollback are part of the release gate.

## Security model

SovereignBot 1.0 is fail-closed on governed actions and unsafe durable state. Browser/network hard denials remain stronger than ordinary allow rules. Governed MCP/computer authority is tied to the exact running worker task. Secret-channel values and credential-shaped fields are kept out of public/operator telemetry surfaces, and the audit chain is integrity checked.

Browser profiles and full-computer recovery backups can contain real logged-in sessions. They are local sensitive state and are **not** part of this GitHub Release.

## Upgrade guidance

Existing pre-1.0 installations should read `docs/v1-migration.md` before upgrading. In particular:

- stop the runtime before taking a recovery backup;
- preserve the external config separately;
- do not delete policy/computer migration markers by hand;
- complete any supported ComputerRegistry migration before creating a new recovery backup;
- use `--include-computer-state` only when browser/profile continuity is intentionally required.

Detailed migration transaction semantics are in `docs/schema-migrations.md`. Backup/restore/export behavior is in `docs/state-backup.md`.

## Supported release validation

The v1.0 release candidate is not published merely because this notes file exists. Publication remains gated on the repository release checklist, including security review, restart/retry/review/repeat-guard soak, no unresolved P0/P1 defects, and a frozen release-candidate commit passing the required Ubuntu/Windows Node 22/24, real Chrome/governed-MCP, and installer checks.

When those gates pass, the final stable version bump on reviewed `main` is validated by CI; only then may the public-release workflow create the immutable `v1.0.0` tag and GitHub Release from the verified artifact set.
